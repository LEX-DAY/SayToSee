# SayToSee — WebRTC-видеовстречи

SayToSee — самостоятельный сервис видеовстреч до 10 участников. Интерфейс
работает на Next.js, а аудио и видео передаются через self-hosted LiveKit SFU.

## Архитектура

- `443/tcp` — HTTPS приложения, API и защищённая WSS-сигнализация LiveKit;
- `7882/udp` — основной WebRTC-медиатрафик через один UDP mux-порт;
- `7881/tcp` — ICE/TCP fallback для сетей, блокирующих UDP;
- `80/tcp` — перенаправление на HTTPS и ACME-проверка сертификата.

LiveKit использует adaptive stream, dynacast, simulcast и RED-избыточность
для Opus. Комната ограничена десятью участниками.

## Качество связи и звук

- **AI-шумодав Krisp** (`@livekit/krisp-noise-filter`): убирает клавиатуру,
  вентилятор и уличный шум, оставляя голос. Включается тумблером «Шумодав»
  перед входом и прямо в комнате; настройка запоминается в браузере.
  При активном Krisp браузерное подавление шума и изоляция голоса
  отключаются, чтобы исключить двойную обработку. Если браузер не
  поддерживает Krisp, автоматически используется нативное подавление шума.
- **Эхоподавление и авто-гейн** включены всегда — ровная громкость без эха;
  Opus кодируется пресетом music (моно, высокий битрейт) с RED
  (устойчивость к потерям пакетов).
- **Видео 720p** с симулякастом h180/h360 и dynacast: качество подстраивается
  под канал каждого участника.
- **Стабильность**: индикатор качества аудио (потери/джиттер/PLC/RTT), баннер
  с причиной при обрыве связи и кнопка «Переподключиться» при ошибке.
  Расширенная политика ретраев держит участника в комнате ~90 секунд при
  обрывах сети — переживает переключение Wi-Fi → LTE. Замьюченный микрофон
  останавливает передачу (экономия канала и батареи).
- **Живой статус сервера**: лендинг проверяет доступность LiveKit через
  `/api/health` и показывает реальное состояние вместо статичного текста.

## Экономия ресурсов

- **Аппаратное кодирование видео**: камера публикуется в H.264 — почти все
  устройства кодируют его блоком на чипе. Программный VP8 в Chrome грузит
  целое ядро; браузеры без H.264 автоматически откатываются на VP8.
- **24 fps** вместо 30 — минус ~20% работы кодера, для разговора перед
  камерой плавности достаточно.
- **Плавные фризы**: `degradationPreference: maintain-framerate` — при
  нехватке CPU или сети браузер снижает разрешение, а не останавливает
  картинку.
- **Krisp по возможностям устройства**: на машинах с ≤4 ядрами CPU
  нейрошумодав работает в режиме low, на остальных — medium.
- **Минимум перерисовок**: секундный таймер вынесен в отдельный компонент
  (не перерендеривает сетку видео), статистика качества опрашивается раз
  в 3 секунды, анимаций в интерфейсе нет.

При создании встречи приложение показывает короткий подписанный ключ. Кнопка
«Копировать ссылку» создаёт приглашение вида:

```text
https://example.com/?key=XXXX-XXXX-XXXX-XXXX
```

Ключ действителен 24 часа. Гость также может ввести его вручную.

## Локальный запуск

Требуется Docker Desktop с запущенным Docker Engine.

```powershell
npm run local:setup
npm run local:up
```

Откройте <http://localhost:3000>. Локальная сигнализация LiveKit доступна на
`ws://localhost:7880`; медиапорты — `7882/udp` и `7881/tcp`.

На Linux:

```bash
npm run local:setup:linux
npm run local:up
```

`.env.local` содержит автоматически созданные ключи LiveKit и секрет подписи
встреч. Файл исключён из Git.

## Запуск на VM с публичным IP

Создайте конфигурацию:

```bash
PUBLIC_IP=203.0.113.10 ./scripts/setup-vm.sh
```

Примените сетевые параметры для WebRTC:

```bash
./scripts/optimize-vm.sh
```

Затем запустите сервисы:

```bash
docker compose \
  --env-file .env.local \
  -f docker-compose.yml \
  -f docker-compose.vm.yml \
  up -d --build --remove-orphans
```

На внешнем firewall должны быть разрешены `80/tcp`, `443/tcp`, `7881/tcp` и
`7882/udp`. Порт LiveKit API `7880/tcp` привязан только к localhost и
проксируется через Caddy.

## Проверка

```powershell
npm test
npm run lint
```

Тесты проверяют production-сборку, WebRTC-зависимости, UDP mux/TCP fallback,
маршрутизацию WSS/API, адаптивные настройки LiveKit и ссылку приглашения.
